# ACP TCK Integration Implementation Plan

> **For agentic workers:** Use the installed pi-subagents workflow-script surface; the parent owns orchestration and acceptance. No commits.

**Goal:** Add a reproducible, isolated ACP v1 compatibility check and non-blocking CI diagnostics without replacing our existing tests.

**Architecture:** Run a pinned upstream acp-tck checkout against the built adapter and real installed Pi, with an isolated deterministic local provider. Keep TCK conformance failures visible in the command exit code and JSON report; only the dedicated CI diagnostic step is non-blocking.

**Tech Stack:** Existing Node/Bun scripts and node:test; uv/Python >=3.14 for the external TCK; GitHub Actions.

**Spec:** The preceding user-approved recommendation and execution request: v1, pinned revision, isolated deterministic runner, initially non-blocking CI, fresh review followed by accepted fixes. ## Task 1: Implement the reproducible TCK diagnostic seam

**Files:** Create scripts/eval-acp-tck.mjs (or equivalently named minimal runner), scripts/fixtures/acp-tck-extension.ts if the existing fixture is too coupled to subagents, test/unit/acp-tck.test.ts; modify package.json, .github/workflows/ci.yml, docs/adapter-reference.md. Reuse scripts/isolated-env.mjs patterns without changing smoke/eval behavior. Avoid changing the existing subagents harness simply to reuse it.

**Interfaces:** An npm `eval:tck` command builds then invokes the runner. Runner accepts an explicit external checkout via `PI_ACP_TCK_DIR`, verifies its exact pinned revision, invokes `uv --project <checkout> run acp-tck --protocol-version 1 ... -- node <absolute built adapter path>`, and writes a report to a documented persistent location outside temporary agent state. Additional CLI args may pass through to TCK if needed, but do not build a general framework. Missing/wrong checkout or missing prerequisites must fail clearly. CI checks out the same pinned upstream revision into runner-temp storage, provisions Python/uv and installed Pi, then runs the npm command. The TCK execution step alone is continue-on-error; upload diagnostics with always().
